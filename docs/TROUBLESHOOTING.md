# Linking The World Temp HA 故障排查

本文适用于 HACS 集成 **Linking The World Temp HA 1.4.1**，最低支持
Home Assistant `2026.9.0`。

## 开始前

- 确认 MC7021 与 Home Assistant 在同一可信局域网，TCP 端口为 `9000`。
- App 建议使用 `Test` 账号，HA 集成使用 `admin` 账号。不要让 App 和 HA 使用同一账号，
  避免会话竞争和相互掉线。
- 未知主机型号或固件先关闭“允许从 HA 控制设备”，确认总控与房间面板的状态稳定上报后
  再开启控制。该集成不保证兼容未记录的协议回复或状态包结构。

## 连接状态

“主机连接阶段”是运行诊断，不是单纯的套接字状态：

| 状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 未连接 | 没有活动会话，或会话已中断。 | 检查局域网、主机供电和端口；等待受限退避重连。 |
| 正在连接 | 正在建立 TCP 连接。 | 短暂出现是正常的。长期停留时检查地址、路由和防火墙。 |
| 正在握手 | TCP 已建立，正在等待协议握手。 | 确认是 MC7021、端口是 9000，并检查固件兼容性。 |
| 正在登录 | 握手已完成，正在进行本地主机认证。 | 等待结果；不要把此状态单独判断为密码错误。 |
| 已就绪 | 已完成认证，并收到可验证的控制器状态流。 | 这是“主机连接”在线的唯一状态。 |

“连接失败类别”会进一步区分 TCP 被拒绝、TCP 超时、握手失败、登录超时、认证被拒绝、
协议不兼容和状态上报中断。它不含主机地址、密码或原始报文。

## 总控环境与故障状态

集成使用已验证的 14 字节总控状态布局提供节能控制回报、温湿度、PM2.5、CO2、
主机故障码和新风滤网故障码。“主机故障状态”和“新风滤网故障状态”均为 Home Assistant
“问题”类型：

- 正常：原始码为 `0`，当前有效状态报文没有报告该类故障；
- 检测到问题：原始码非零，同时创建 `ERROR` 级 Home Assistant Repair，交由设备技术资料或
  维护人员解释；
- 未知或不可用：尚未收到严格匹配的完整状态块，或当前固件发送了未验证的布局。

同一故障码持续上报不会重复写入错误日志；故障码发生变化时，同一个 Repair 会更新为新
原始码并记录一次变化。主机重新上报 `0` 后，Repair 自动清除并记录恢复信息。此提醒只反映
主机上报，不会禁用或阻断总控和房间面板控制。

具体整数由“主机故障原始码”和“新风滤网故障原始码”两个独立诊断传感器显示，`0` 显示
“无故障”。Home Assistant 2026.9 用户可在安全面板编辑器中将两个问题实体加入“活动警报”
或收藏；活动警报需要用户自行选择实体和严重程度。尚未收到有效总控状态或主机断开时，
两个问题实体和两个原始码传感器都会显示不可用，避免把旧数据误认为当前状态。

如果总控开关、模式等旧状态正常，但这些新实体始终未知，请先下载集成诊断并确认是否有
解码失败计数；不要把未知字节偏移手工套用为测量值，也不要为了显示数值修改客户端 ID、
总控 MAC 或开启控制权限。

温度和湿度来自科技系统独立传感器经 Mo-Bus 汇总到主机的上报，不代表 MC7021 机身
测量值。`1.2.0` 仅把实体显示名从“主机温度/主机湿度”修正为“温度/湿度”，unique ID
没有改变。

## 节能控制

“节能控制”是科技系统总控的常驻开关，直接显示主机回报的节能状态。使用写入实体必须
保持“允许从 HA 控制设备”开启；关闭全局控制权限后，该实体仍可展示状态，但不能发送命令。

命令码 `0x06` 的发送成功不是确认。集成会等待完整状态块中的节能位匹配目标值，并沿用
总控命令队列、查询兜底、超时和 Repair 逻辑。若显示等待确认后超时：

1. 检查主机连接阶段是否为“已就绪”，以及 App 与 HA 是否复用了同一账号；
2. 查看“节能控制”是否仍随 App 操作持续更新；
3. 下载脱敏诊断，检查总控状态与命令确认计数；
4. 不要尝试 `0x60` 批量命令，本集成没有实现该路径。

自动化测试覆盖四种运行模式和居家/离家组合；未知主机型号或固件仍建议先观察 App 与 HA
的双向状态回传，再用于自动化。

## 账号、错误密码与重新认证

初次添加集成时，只有主机发送了已捕获的、明确的登录拒绝响应，才会立即显示这条精确
UI 信息：

> 主机拒绝登录，请检查本地主机账号和密码

这是 `invalid_auth`。请检查 MC7021 的本地主机账号和密码，并确认 HA 使用的账号没有与
App 复用。

已加载的集成在运行期间收到同一种明确拒绝时，不会创建第二个配置项；它会为原配置项
启动“重新验证”流程，只要求输入用户名和密码。提交且验证成功后，Home Assistant 更新
原条目并重新加载；在此之前集成暂停自动登录重试。

**不要把登录超时当作密码错误。** 登录超时、EOF、TCP 关闭、未知登录回复、网络超时或
握手失败都没有足够证据说明密码错误。它们会保留各自的失败类别和重连行为，而不是显示
`invalid_auth`。

## Repairs

在“设置 -> 系统 -> Repairs”中处理以下问题：

- **主机登录连续超时**：只有连续三次登录阶段超时才创建。先检查主机在线状态、端口
  `9000`、账号和密码；Repair 会引导到重新认证。一次成功认证会清除计数和 Repair。
- **主机协议不兼容**：主机返回了当前集成不支持的握手或登录/协议回复。确认 MC7021
  型号、固件和端口；不要为了绕过此问题盲目修改客户端 ID 或 MAC。兼容的成功会话才会
  清除这个 Repair。
- **六恒科技系统控制命令连续未确认**：只有连续三条已经穷尽确认与恢复路径的最终命令
  才创建。检查主机连接是否稳定，并确认 App 和原生集成没有复用同一账号；
  下载集成诊断查看命令队列和确认计数。下一条命令确认成功后会自动清除这个 Repair。
- **主机故障/新风滤网故障**：任一对应原始码非零时立即创建严重 Repair。
  查看原始码并检查科技系统或滤网；在没有厂商资料时不要自行猜测代码含义。相同码不会
  重复告警，变码会更新提示，主机上报 `0` 后自动清除。该 Repair 不会阻断控制。
- **房间温控面板已 30 天未上报**：这是一个手动清理建议，不会自动删除任何设备。Repair
  仅显示最新房间名、缩短 MAC 和最后有效报告时间；确认后才删除本集成拥有的实体、可安全
  删除的设备记录和保存的面板记录。取消或忽略不会改变数据。以后收到同一面板的有效报告
  时，它会被重新发现并清除 Repair。

### 30 天的准确含义

阈值是 `30 * 24 * 60 * 60` 秒的**已观察缺席**，并非“最后报告日期距今 30 天”。只有
控制器为 `已就绪`、有效控制器状态流持续到达、且该面板未报告时才累积。HA 停机、控制器
断开、登录或握手失败、状态流停滞、无效状态数据都会暂停；重新连接不会抹去之前已累积
的时间。新的有效面板报告会立即恢复可用、将计数归零并移除过期 Repair。

面板短期可用性仍由 `thermostat_offline_after` 控制（`0` 关闭短期检测）；它独立于上面的
30 天清理资格。

## 隐私安全地收集诊断和日志

诊断中的 `runtime.status_freshness` 分别显示整体状态流和总控状态的年龄。房间状态持续
更新不代表总控一定正常；总控超过“主机静默重连时间”后先发合并查询，经过命令确认超时
与 10 秒中的较大宽限仍无有效回报，才断开重连。恢复查询不会根据缓存状态假装确认命令。

`runtime.command_history` 最多保留最近 30 条控制记录，并与 `runtime.panels` 共享匿名
面板标签。`queued`/`waiting` 表示尚在排队或等待；`confirmed` 表示已匹配主机状态；
`unchanged` 表示与现有状态或待确认意图相同而未发送；`superseded` 表示被较新意图替换；
`timeout`、`failed`、`blocked`、`disconnected` 分别表示最终确认超时、发送失败、规则阻止
和会话结束。发送次数是尝试次数，不证明主机收到或执行。

TCP 写入等待超过 8 秒会终止异常连接并重连；关闭清理超过 3 秒会强制终止传输。
这些截止时间包含等待锁或任务清理，不会无限阻塞重载。诊断记录只保存在内存中，收集时
请在重载或重启之前下载。

1. 在“设置 -> 设备与服务 -> Linking The World Temp HA”下载诊断。
2. 只收集复现问题前后的一小段 Home Assistant 日志，并同时提供连接阶段、失败类别和
   是否出现 Repair。
3. 不要发送配置条目导出、截图中的账号/地址、主机密码、客户端 ID、MAC、房间名、密钥、
   令牌或任何原始 TCP/YASHCP 十六进制报文。
4. 不要为了排障打开或复制原始协议转储。生产日志不需要原始帧即可关联连接阶段、计数、
   重试和命令确认状态。

诊断会匿名化面板和房间为 `panel_01`、`room_01` 等本次导出内标签，并移除家庭标识。
详见 [PRIVACY.md](PRIVACY.md)。

### 异常协议帧摘要

出现 `Discarded malformed YAS HCP payload` 后，下载诊断并查看
`runtime.parser_anomalies`。这里最多保留最近 8 条结构摘要：

- `outer_length_declared` 与 `payload_bytes_consumed`：外层声明的长度和解析器按该声明取出的
  字节数；
- `body_length_declared` 与 `payload_length_expected`：协议头声明的正文长度，以及据此推算的
  完整载荷长度；
- `magic_header_valid` 与 `trailer_present`：协议头和结束符是否符合当前已知格式；
- `kind`、`opcode`、`sequence`：结构足够完整时读取到的帧类型、操作码和序列号；
- `recovery` 与 `immediate_recovery`：下一有效帧是否立即恢复解析。`next_valid_frame` 表示
  没有经过另一条异常帧便恢复，`after_additional_anomalies` 表示经过更多异常后恢复，
  `pending` 表示导出诊断时尚未观察到后续有效帧。

摘要不包含原始报文或正文。如果外层长度与协议头推算长度长期呈现同一种固定差值、帧类型
也稳定一致，可能是尚未适配的主机协议变体；如果长度和结构随机变化，则更像传输损坏或帧
边界异常。请连同警告发生时间和脱敏诊断提交，不要附带十六进制原始流量。
